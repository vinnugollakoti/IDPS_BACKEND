# IDPS Backend API Reference

This document describes every API currently registered by the Express backend in `server/server.ts`.

## Server Overview

- Runtime: Express + TypeScript
- Entry point: `server/server.ts`
- Port: `process.env.PORT`
- Body parser: JSON via `express.json()`
- CORS: enabled globally
- Auth: JWT Bearer token on protected routes

## Base URL

Use the deployed server URL or local server URL:

```text
http://localhost:<PORT>
```

## Authentication

Protected APIs use the `auth` middleware.

Header:

```http
Authorization: Bearer <jwt_token>
Content-Type: application/json
```

JWT payload generated by the backend:

```json
{
  "userId": 1,
  "role": "PRINCIPAL"
}
```

Token expiry: `7d`.

Auth failures:

```json
{ "message": "No token" }
```

```json
{ "message": "Invalid token" }
```

## Common Notes

- All request bodies are JSON.
- IDs are numeric database IDs.
- Date values should be sent as ISO strings unless noted otherwise.
- Several handlers return nonstandard HTTP codes such as `600` or `700`; these are documented exactly as implemented.
- Decimal values from Prisma may serialize as strings or numbers depending on Prisma/runtime behavior.
- APIs do not currently implement pagination.

# Auth APIs

## POST `/auth/login`

Starts OTP login for a registered user email.

Auth: none

Body:

```json
{
  "email": "parent@example.com"
}
```

Required:

| Field | Type | Notes |
|---|---|---|
| `email` | string | Must already exist in `User.email` |

Success response:

```json
{
  "message": "OTP Sent, valid for 5 minutes",
  "data": {
    "otp": "123456",
    "otpExpiry": "2026-03-26T10:05:00.000Z"
  }
}
```

Errors:

| Status | Message |
|---|---|
| `400` | `Email required` |
| `600` | `User is not registered by the school.` |
| `400` | `Error executing login request` |

Implementation note: the OTP is returned in the response as well as emailed.

## POST `/auth/otp-verify`

Verifies OTP and returns a JWT.

Auth: none

Body:

```json
{
  "email": "parent@example.com",
  "otp": "123456"
}
```

Required:

| Field | Type | Notes |
|---|---|---|
| `email` | string | User email |
| `otp` | string | 6-digit OTP |

Success response:

```json
{
  "message": "Logged in Successfully",
  "token": "<jwt_token>",
  "user": {
    "id": 1,
    "name": "User Name",
    "email": "parent@example.com",
    "role": "PARENT",
    "gender": "MALE",
    "parent": {},
    "teacher": null
  }
}
```

Errors:

| Status | Message |
|---|---|
| `400` | `User not found` |
| `400` | `Invalid OTP` |
| Intended `400` | `OTP expired` |
| `400` | `Logged in failed due to server, contact developer` |

Implementation note: expired OTP path currently calls `res.json(400).json(...)`, which is a bug.

Allowed roles: `PRINCIPAL`, `RECEPTIONIST`

Body:

```json

  "name": "Parent Name",

  "relation": "Father",
```

Required:

| Field | Type | Notes |
|---|---|---|
| `name` | string | Parent/user name |

| `gender` | `MALE` or `FEMALE` | Stored on `User` |
| `phone1` | string | Stored on `Parent` |

Optional:

| Field | Type | Notes |
|---|---|---|
| `relation` | `Father`, `Mother`, `Guardian` | Stored on `Parent` |
| `phone2` | string | Secondary phone |
| `type` | `MOTHER`, `FATHER`, `GUARDIAN` | Accepted in body but currently not saved |


## POST `/student/bulk-import-students`

Imports many students into one class. Creates/reuses father and mother parent records and links them to each student.

Auth: required

Allowed roles: `PRINCIPAL`, `RECEPTIONIST`

Body:

```json
{
  "classId": 1,
  "rows": [
    {
      "rowNumber": 1,
      "admissionno": "A001",
      "name": "Student Name",
      "gender": "Male",
      "dob": "20/05/2018",
      "adharnumber": "123412341234",
      "pincode": "500001",
      "mothertongue": "Telugu",
      "socialcategory": "OC",
      "bloodgroup": "O+",
      "admissiondate": "2026-03-01",
      "height": 120,
      "weight": 25,
      "address": "Student address",
      "parents": {
        "father": {
          "name": "Father Name",
          "phone": "9000000001",
          "aadhar": "111122223333",
          "qualification": "BTech"
        },
        "mother": {
          "name": "Mother Name",
          "phone": "9000000002",
          "aadhar": "444455556666",
          "qualification": "BA"
        }
      }
    }
  ]
}
```

Required:

| Field | Type | Notes |
|---|---|---|
| `classId` | number | Existing class ID |
| `rows` | array | At least one row |
| `rows[].name` | string | Required after normalization |
| `rows[].gender` | string | Accepts `M`, `MALE`, `BOY`, `F`, `FEMALE`, `GIRL` |

Optional row fields:

| Field | Type | Notes |
|---|---|---|
| `rowNumber` | number | Used in reports |
| `admissionno` | string | Defaults to `TEMP-<classId>-<rowNumber>` |
| `dob` | string | Supports ISO, `dd/mm/yyyy`, `dd-mm-yyyy`, and JS parseable dates |
| `adharnumber` | string | Digits are normalized |
| `pincode` | string | Digits are normalized |
| `mothertongue` | string | Normalized to enum |
| `socialcategory` | string | Normalized to enum |
| `bloodgroup` | string | Normalized to enum |
| `admissiondate` | string | Flexible date parser |
| `height` | number/string | Integer-like value |
| `weight` | number/string | Integer-like value |
| `address` | string | Student address |
| `parents.father` | object | Father input |
| `parents.mother` | object | Mother input |
| `fatherName`, `motherName`, `mobileNumber`, `fatherAadhar`, `motherAadhar`, `qualification` | string | Flat fallback fields supported by importer |

Parent matching order:

1. Same `adharnumber` and relation
2. Same `phone1` and relation
3. Same `name` and relation

Success response:

```json
{
  "message": "Import completed",
  "data": {
    "classId": 1,
    "className": "1-A",
    "createdStudents": 1,
    "createdParents": 2,
    "createdMothers": 1,
    "createdFathers": 1,
    "linkedParents": 2,
    "linkedRelations": 2,
    "reusedParents": 0,
    "skippedRows": 0,
    "failedRows": [],
    "createdStudentIds": [1],
    "stepTrace": []
  }
}
```

Errors:

| Status | Message |
|---|---|
| `403` | `Unauthorized request` |
| `400` | `Valid classId is required` |
| `400` | `No rows received for import` |
| `404` | `Class not found for the provided classId` |
| `500` | `Failed to import student data` |

# Teacher Attendance APIs

These routes are mounted at `/teacher`.

## Supabase Environment Variables

Teacher attendance selfie upload uses Supabase Storage directly.

```text
SUPABASE_URL=https://<project-ref>.supabase.co
SUPABASE_SERVICE_ROLE_KEY=<service-role-key>
SUPABASE_TEACHER_ATTENDANCE_BUCKET=teacher-attendance
TEACHER_ATTENDANCE_MAX_IMAGE_BYTES=5242880
```

Notes:

- `SUPABASE_TEACHER_ATTENDANCE_BUCKET` defaults to `teacher-attendance`.
- `TEACHER_ATTENDANCE_MAX_IMAGE_BYTES` defaults to `5MB`.
- The bucket must exist in Supabase Storage.
- `selfieUrl` is saved as a public object URL. If the bucket is private, use `selfiePath` to create signed URLs from Supabase.

## POST `/teacher/attendance`

Submits today's attendance for the authenticated teacher by uploading a live selfie to Supabase Storage and saving the attendance metadata in the database.

Auth: required

Allowed roles: `TEACHER`

Headers:

```http
Authorization: Bearer <teacher_jwt_token>
Content-Type: application/json
```

Body:

```json
{
  "imageBase64": "data:image/jpeg;base64,/9j/4AAQSkZJRgABAQ...",
  "capturedAt": "2026-07-18T08:45:00.000Z",
  "latitude": 17.385,
  "longitude": 78.4867,
  "accuracy": 18.5,
  "deviceId": "teacher-phone-123"
}
```

Alternative raw base64 body:

```json
{
  "imageBase64": "/9j/4AAQSkZJRgABAQ...",
  "imageMimeType": "image/jpeg"
}
```

Required:

| Field | Type | Notes |
|---|---|---|
| `imageBase64` | string | Data URL or raw base64 image |

Required only for raw base64:

| Field | Type | Notes |
|---|---|---|
| `imageMimeType` | `image/jpeg`, `image/png`, `image/webp` | Not needed when `imageBase64` is a data URL |

Optional:

| Field | Type | Notes |
|---|---|---|
| `capturedAt` | Date string | Defaults to server time. Cannot be more than 5 minutes in the future |
| `latitude` | number/string | Must be between `-90` and `90` |
| `longitude` | number/string | Must be between `-180` and `180` |
| `accuracy` | number/string | Must be `0` or higher |
| `deviceId` | string | Trimmed and capped to 120 characters |

Validation:

- Only `JPEG`, `PNG`, and `WEBP` images are accepted.
- Image size must be within `TEACHER_ATTENDANCE_MAX_IMAGE_BYTES`.
- Image bytes must match the declared image type.
- A teacher can submit only one attendance record per attendance date.

Success response:

```json
{
  "message": "Teacher attendance submitted successfully",
  "data": {
    "id": 1,
    "teacherId": 1,
    "attendanceDate": "2026-07-18T00:00:00.000Z",
    "capturedAt": "2026-07-18T08:45:00.000Z",
    "submittedAt": "2026-07-18T08:45:05.000Z",
    "selfieUrl": "https://<project-ref>.supabase.co/storage/v1/object/public/teacher-attendance/teachers/1/2026-07-18/...",
    "selfiePath": "teachers/1/2026-07-18/....jpg",
    "selfieMimeType": "image/jpeg",
    "selfieSizeBytes": 245000,
    "latitude": 17.385,
    "longitude": 78.4867,
    "accuracy": 18.5,
    "deviceId": "teacher-phone-123",
    "ipAddress": "127.0.0.1",
    "userAgent": "Mobile App",
    "teacher": {
      "user": {
        "id": 1,
        "name": "Teacher Name",
        "email": "teacher@example.com",
        "role": "TEACHER"
      }
    }
  }
}
```

Errors:

| Status | Message |
|---|---|
| `401` | `Invalid token payload` |
| `403` | `Only teachers can use teacher attendance` |
| `404` | `Teacher profile not found` |
| `409` | `Teacher attendance already submitted for today` |
| `400` | Validation error message |
| `500` | `Supabase storage is not configured` |
